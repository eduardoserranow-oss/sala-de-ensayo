# FORTISSIMO Desktop

FORTISSIMO Desktop is a minimal Windows Electron shell around the production FORTISSIMO web app.

## Architectural rule

FORTISSIMO Web remains the source of truth. The Desktop shell must not duplicate Vibe Roulette, authentication, music logic, datasets, S.K.Y. Keys, or cloud state. Native Windows capabilities are exposed only through a narrow preload bridge.

## Phase 3 capabilities

- Loads the production FORTISSIMO app over HTTPS (`https://fortegym.vercel.app/`).
- Uses an explicit persistent Electron partition (`persist:fortissimo-main`) for the FORTISSIMO profile.
- Reuses the existing FORTISSIMO login and cloud account flow; there is no separate Desktop account system.
- Respects the existing “Mantener sesión iniciada” behavior.
- Exposes only `window.fortissimoDesktop` to the web app.
- Reports `persistent-session` and `midi-stage` capabilities.
- Adds `window.fortissimoDesktop.stageMidiPair(payload)` as the only new privileged request surface.
- Accepts exactly two staged MIDI files: Foundation + Texture.
- Re-validates the renderer origin in the Electron main process before accepting MIDI.
- Validates simple `.mid` filenames, byte ranges, payload size, Standard MIDI File `MThd`/`MTrk` structure, format 0 and one-track headers.
- Keeps staged MIDI bytes in Electron main-process memory only.
- Automatically discards staged MIDI when the renderer is destroyed.
- Keeps Node.js integration disabled, context isolation enabled and renderer sandboxing enabled.
- Does not write MIDI to disk yet.
- Does not implement native drag-and-drop yet.

## Phase 3 boundary

The existing Vibe Roulette Song Starter export remains the MIDI source of truth. It already produces exactly two DAW-ready files (`Foundation` and `Texture`) with the current pianist timing, velocities and S.K.Y. preset metadata. Phase 3 creates only the safe transport contract that can receive those generated bytes from the web renderer.

Phase 4 can consume the staged in-memory pair, write temporary `.mid` files and invoke Electron's native drag only after that next privilege is deliberately added and tested.

## Development

Requirements: Node.js 22+ and npm.

```powershell
cd desktop
npm install
npm start
```

To point the shell at another approved HTTPS FORTISSIMO deployment while testing:

```powershell
$env:FORTISSIMO_APP_URL="https://fortegym.vercel.app/"
npm start
```

To enable DevTools for local testing:

```powershell
$env:FORTISSIMO_DEVTOOLS="1"
npm start
```

## Validation

```powershell
npm test
```
